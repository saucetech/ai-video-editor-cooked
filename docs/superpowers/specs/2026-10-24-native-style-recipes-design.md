# Analyzed styles, advanced captions and editable hook recipes

## Intent and authority

The owner requested advanced caption styles and hook motion graphics, editable in Resolve and visibly good quality. Their clarification makes faithful transfer of already analyzed styles the priority: a successful import is insufficient. Prior standing authorization is to keep building and fixing until the feature works well, without repeated setup/implementation approval questions. Use the existing feature checkout and native inline execution; no paid generation, uploads or new runtime packages.

Add three original hook recipes (hero reveal, outline draw, prompt-to-result) alongside existing title/lower-third fades. These are the first native recipe set, not completion of all seven competitor hook families. Behind-subject, asset walls/carousels and profile scrolling remain explicit inventory gaps.

Select an existing saved analysis from the configured library. Keep measured values, inferred visual notes and defaults distinct. Font substitution, missing word timing, unsupported easing/effects, face placement and untaken analysis fields must be reported rather than silently described as faithful. Applying a style must not overwrite source transcript/ranges or original analysis files. Captions remain explicitly enabled; analyses saying absent do not erase a user's opt-in caption decision.

Existing local analyses include a dark serif/glass reference whose OCR missed captions; its notes and closest-font name are estimates. Treat them as inferred. Builder call: use installed Arial/Georgia families for the first portable native implementation and name any substitution. Never claim an exact original font without verifying that family in both renderers.

## Caption behavior

Defaults preserve old boards and historical approved bundles. Per passage expose treatment, phrase grouping, emphasis and placement while retaining caption correction and enable controls. Clean and editorial captions use restrained typography and contrast support, with at most two lines per phrase. Spotlight emphasizes one real spoken word at a time using source word timestamps; correction/alignment must be checked, and unavailable timing produces a clear static/passsage-timing mode, not fabricated speech synchronization. Explicit line breaks, source omission mapping and corrected SRT remain supported.

A shared, deterministic scene description specifies canvas, text runs, fonts/colors, geometry and integer-frame animation samples. Both Pillow/FFmpeg preview and generated native Fusion nodes consume it. Text remains in visible Text+ nodes, never hidden editable text above a baked carrier. Spotlight may use separately named word nodes; users can edit each word in Fusion, with reflow performed by rebuilding the board preview. Surface this limitation. Native text, sizes, colors, fonts and motion sample values are read back.

## Hook behavior

Hero reveal: a source-linked statement settles with restrained scale/opacity and an accent rule. Outline draw: an original drawn frame/underline directs attention to the entered statement. Prompt-to-result: an explicit prompt and result reveal in sequence, with each text field independently editable. No invented statistics or automatic copy. A selected local B-roll clip remains a native separate clip beneath graphics. Keep hook graphics clear of the caption region. Reject or explicitly simplify durations that cannot sustain a readable hold; no violent one-frame scale jumps.

## Transfer proof

Add an explicit Compare Resolve action after native delivery. It reads the saved timeline/visual bundle, exports selected actual Resolve frames to the revision, and presents paired preview/native stills plus a transfer report. Preserve current project/timeline/page/timecode on success; unknown outcomes follow existing quarantine rules. Only approved ready revisions with known native timeline IDs may be inspected. Generated proof files stay under the revision; no arbitrary export destination, source modification or automatic render-queue mutation.

Use the installed Project.ExportCurrentFrameAsStill API, with a bounded helper allowlist addition and export-path validation. Prove it in the dedicated synthetic QA project before product claims. A proof records revision/bundle identity, native timeline ID, checked control values, timestamps and file hashes. Manual native changes appear as divergence; never overwrite them. Earlier timelines remain intact through a new revision. Readback alone does not certify appearance; a capture alone does not certify editability. Do not label pixel-perfect or total style transfer from a successful API return.

## Quality acceptance

Use the selected analyzed serif/dark reference plus synthetic timing/style fixtures. Build original demonstration footage with neutral interface content and authored captions, not competitor media or fabricated customer results. Inspect readable held frames and full short playback in landscape and portrait. Check typography hierarchy, line wrapping, minimum text size, panel/word bounds, contrast, reserved caption region, stable word pacing and eased motion. Preserve source audio. Export actual native proof frames at start, entrance completion, hold and exit; compare geometry/color/timing and fix visible mismatches. Publish exact approximations and remaining limits with the preview.

Tests cover legacy approvals; style snapshot integrity and untrusted paths/values; missing/conflicting/changed word timings; removed passage offsets; dense text and very short hooks; integer-frame native curves; actual frame export destination guards; stale/changed native proof; UI controls surviving save/approve; and ordinary correction preserving prior finishing. Run the full Python/UI/plugin checks and relevant offline demos. A fresh final reviewer checks the whole change, followed by one verified fix pass.

## Boundaries and feedback

No universal editing-quality or savings claim, no promise of a perfect clone of a sampled creator, no automatic face-occlusion guarantee without representative footage, no native Subtitle/karaoke claim for passage-only input, no flattened whole-edit fallback presented as editable graphics. Record actual verification and limits in the existing board/Resolve guides, feature inventory and private owner evidence. Feedback identifies style snapshot, passage, recipe and the expected native frame/control.
