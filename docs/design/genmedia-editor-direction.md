# GenMedia Editor interface direction

Mode: Operate. User-selected direction: Apple-inspired dark Liquid Glass. Original request: replace cooked branding and the generic AI appearance throughout the editor. The follow-up explicitly asked to use Aura.build for inspiration.

## Direction contract

- The video and decisions lead. The board presents a large player, a real source-interval strip, compact passages, and cut approval/Resolve delivery controls.
- Use the platform sans stack, a restrained graphite palette, pale blue-white primary actions, rounded controls, and translucent floating navigation.
- Glass belongs to the shell and transient controls. Transcript text, media, planning fields, and status remain readable against stable surfaces.
- A passage's disclosure hides repeated fields, while its summary retains the presence of notes and non-default zoom. Keep/remove and protected hold remain directly available.
- Mobile stacks the working areas without horizontal page scrolling. Preserve the explicit saved light preference; default new/system appearance is dark as requested.
- Reduced motion, reduced transparency, increased contrast, and unsupported backdrop-filter have fallbacks.
- No speculative captions, generated footage, fake audio waveforms, unverified benefit claims, or stock footage masquerading as a user project.

## References inspected

- [Aura glass components](https://www.aura.build/components?q=glass), including Glass Navigation Header and Glass Chat Support Card. Popular sorting is a gallery setting, not an objective design ranking.
- [Aura Liquid Glass template](https://www.aura.build/templates/liquid-glass). Public gallery thumbnail and product page inspected; its embedded preview returned a load error. No paid template code/assets were copied.
- [Apple: Meet Liquid Glass](https://developer.apple.com/videos/play/wwdc2025/219/), especially material hierarchy and accessible contrast.

This is a web interpretation, not the native Apple rendering system. Earlier GenMedia prototype colors are superseded for this editor by the user's explicit follow-up.

## Repeatable UI change procedure

Trigger: a meaningful editor UI change. Inputs: current PRODUCT.md, DESIGN.md, real route/state, relevant owner direction, known behavior contracts.

1. Read the relevant implementation and inspect the existing route. Establish the user's task and actual capability limits.
2. Use shared genmedia.css tokens, then route-scoped layout rules. Keep storage paths, source assets, authentication, and existing timelines intact.
3. Build the complete change, including loading/error/empty/disabled/focus states. Use actual source data for timelines and durations.
4. Run the relevant behavior tests and home/review demos when their shell changes. Inspect desktop and phone-width pages in one batch; correct material findings together, then confirm once.
5. Record screenshots, observed test results, and remaining limits. Request independent review when the chosen design skill requires it. Update DESIGN.md for actual system changes.

Deliverables: working routes, maintained design system, regression results, screenshot evidence. Acceptance: visible GenMedia identity; readable editor controls; source/review/approval routes continue working; no horizontal overflow at the tested widths; no new unauthorized generation or uploads.

Feedback path: owner comments on the live editor take precedence over generated screenshots or an internal reviewer. Preserve the exact correction in the maintained design record and apply it across the shared shell.
